# ASD-STE100 digest

A simplified, example-led digest of ASD-STE100 Simplified Technical English (STE), for agents applying the writing skill.

ASD-STE100 and TechScribe material is used with the owners' permission. Further reading: techscribe.co.uk/techw/asd-simplified-technical-english.htm.

This is not the specification. The official spec is free after registration at asd-ste100.org and is the only authority. Never claim strict STE conformance from this file alone. The spec is revised periodically; check the current issue when conformance matters.

## What STE is

STE is a controlled language: a restricted subset of English for technical documentation. It was built in aerospace so instructions stay unambiguous for readers whose first language is not English. It has two parts:

1. **Writing rules**: grammar and style constraints, digested below.
2. **A controlled dictionary**: about 900 approved words, each with one approved meaning and part of speech. It is bundled here as `dictionary.json` (extracted from a registered Issue 9 copy; used with permission). Consult it for approved words, approved meanings, and replacements for unapproved words. The substitution table below is a quick-reference sample of its pattern.

## Words

- Use one term for one thing, every time. Synonym variety is a defect, not a style.
  - Don't: "Install the driver", then "Set up the driver", then "Load the driver".
  - Do: pick one verb and keep it for the whole text.
- Use each word in only one sense. If "close" means "shut", use "near" for proximity.
- Avoid idioms, slang, and figurative language.
  - Don't: "The service falls over under load."
  - Do: "The service fails under load."
- STE uses American English spelling. The substitution table follows it.

## Sentences

- Max 20 words in an instruction, 25 in a description.
  - Don't: "Before you start the installation procedure, it is important to make sure that the power supply has been fully disconnected from the unit."
  - Do: "Disconnect the power supply before you install the unit."
- One instruction per sentence.
  - Don't: "Press Enter, wait for the prompt, and then type your password."
  - Do: three steps, one action each.
- One topic per paragraph. Max six sentences per paragraph.
- Do not omit articles, subjects, or verbs to save words.
  - Don't: "Connect cable to port."
  - Do: "Connect the cable to the port."
- Use vertical lists for steps, options, and complex conditions instead of long joined sentences.

## Verbs

- Active voice. Name the actor when the actor matters.
  - Don't: "The file is deleted."
  - Do: "The installer deletes the file."
- Imperative mood for procedures.
  - Don't: "You should restart the service."
  - Do: "Restart the service."
- Simple tenses: present, past, simple future. The present perfect, past perfect, and progressive forms are not approved.
  - Don't: "The installer is copying the files."
  - Do: "The installer copies the files."
  - Don't: "The operator has adjusted the linkage."
  - Do: "The operator adjusted the linkage."

## Nouns

- Keep noun groups short, two or three words. Use prepositions to show the relationships.
  - Don't: "the network interface card configuration settings"
  - Do: "the settings for the network interface card"
- Do not turn nouns into verbs.
  - Don't: "Oil the valve."
  - Do: "Apply oil to the valve."

## Procedures

- Numbered steps, imperative, one action per step.
- Put the condition before the action.
  - Do: "If the light is red, stop the motor."
- Put safety instructions first. Start them with a clear command or condition.
  - Do: "WARNING: Disconnect the power supply before you open the cover."

## What STE allows beyond the dictionary

Domain technical terms, product and manufacturer names, part numbers, code, and identifiers are allowed. Do not flag or simplify them. The checker below never flags them, because it only matches known-unapproved entries from the table above.

## Final-pass checklist

1. Every instruction is 20 words or fewer; every description 25 or fewer.
2. One instruction per sentence; one topic per paragraph.
3. Active voice; the actor is named where it matters.
4. The same term is used for the same thing throughout.
5. No words from the substitution table.
6. Lists are used for steps and complex conditions.
7. House rules: no em dashes, no emojis.

## Technical terms

The dictionary is a general vocabulary. Domain terms are allowed as technical nouns and technical verbs, but declare them deliberately:

1. Pick one canonical term per concept. If a project uses several names for one thing (for example: arm, cargo arm, loading arm), choose one and use it everywhere.
2. Record the term in technical-nouns.txt so the checker treats it as approved.
3. Use a technical noun only as a noun, and a technical verb only as a verb.
4. Declare a technical term only when no approved dictionary word covers the concept.

## Deterministic checker

Run the checker before the final pass, from the skill directory:

```bash
python check.py <file>        # or pipe text on stdin
```

Requires `pip install spacy` and `python -m spacy download en_core_web_sm`.

By default it flags words from the substitution table above, em dashes, emojis, and sentences over 25 words. Matching uses lemma and part of speech, so noun uses of verb-only words do not flag. It ignores code fences, inline code, and tables.

Modes:

- `--ste`: also check against the full dictionary in `dictionary.json`.
- `--unknown`: also list words that are absent from the dictionary and the glossary, for glossary review.

Phrases in `technical-nouns.txt` never flag; add project terms there. A `technical-nouns.txt` in the current directory also applies, for project-level glossaries. Exit code 1 when it flags anything, 0 when clean.
